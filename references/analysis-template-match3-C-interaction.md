# 三消/方块消除类分析模板 — Module C: 交互与系统

> 适用于：Candy Crush / Sweet Sugar 类、宝石迷阵类、任何"交换相邻棋子凑成 3+ 连消除、按目标完成关卡"的网格消除游戏

## 使用说明

本模板是三消类分析的第 3 个模块（共 3 个）。执行顺序：A → B → C。

**前置依赖**：Module A 的实体 ID 清单 + Module B 的实体属性数据。

**认知任务类型**：交叉推理。横跨匹配规则、重力 / 下落、连锁、目标推进等多个系统做交叉对比，推断 bot 决策必须依赖的演化规律。

**产出**：交互规则与系统演化文档。

**评估重点**：逻辑一致性——匹配 / 重力 / 连锁规则是否与代码一致？目标推进路径是否被正确建模？

> **三消的"交互"核心**：不是实体间碰撞，而是 **"一次交换 → 触发哪些匹配 → 棋子如何下落补充 → 触发哪些连锁 → 推进哪些目标"** 这条因果链。Module C 要把这条链的每一环都摸清，因为 bot 的评分函数本质是在**模拟这条链并打分**。

## Module C: 交互与系统

### C.1 交换→匹配→消除规则（最高优先）

精读交换、匹配检测、消除代码，回答：

| 字段 | 说明 | 为什么 bot 必须知道 |
|------|------|---------|
| 合法交换条件 | 什么交换被允许？（必须凑成 3+ 连才生效，还是任意交换都执行？） | 决定 bot 能否做"无消除的布局交换" |
| **非法交换是否回退** | 不构成匹配的交换是否被游戏**撤销还原**？ | **关键**：若回退，则 bot 无法靠"连续多步摆出特殊糖"——无法跨回合 setup，只能在单步内成型 |
| 匹配判定 | 3 连 / 4 连 / 5 连 / L/T 形的判定规则 | bot 模拟匹配的依据 |
| 消除连带 | 一次消除会带走哪些（仅同色 3 连？相邻块是否受波及？） | 影响评分：一次交换的真实收益 |
| 特殊糖生成触发 | 哪种形状在哪个位置生成特殊糖 | bot"主动攒特殊糖"的依据 |

**强制结论**：用一句话写明本游戏**是否回退非法交换**。
- **回退**（最常见）→ bot **无法跨回合 setup**，特殊糖必须在单步匹配中直接成型；评分只能基于"当前这步的即时收益 + 可立即激活的已有特殊糖"。
- **不回退** → bot 可做多步布局，评分可含"为下一步创造机会"的前瞻。

> 本次实战为"回退"型：这直接决定了求解器是**贪心单步**架构，而非多步搜索——判断错会让整个策略架构选型跑偏。

### C.2 重力与下落系统（碎片棋盘的关键）

精读棋子下落 / 补充代码，回答：

| 字段 | 说明 | 为什么 bot 必须知道 |
|------|------|---------|
| 下落方向 | 消除后空格如何被填补（上方棋子下落？） | 配合 B.1 行号方向确认 |
| **下落是否沿垂直列** | 规则矩形棋盘沿垂直列；**碎片"岛屿"棋盘可能沿预计算的"下落序列"拐弯** | **关键**：ReachBottom / 原料类目标必须按真实下落路径清障，垂直列启发式在碎片棋盘上会找错阻挡格 |
| 下落序列读取 | 若有预计算下落路径（如每格的 sequence + orderInSequence），如何读取、哪端是出口 | 序列感知路由的数据来源 |
| 生成器入口 | 新棋子从哪些格子补充进场 | 影响"还能不能凑出某色"的判断 |
| 连锁（级联）规则 | 下落后自动形成的新匹配是否连锁触发、是否额外计分 | 影响一次交换的真实收益估计 |

> **碎片棋盘 + ReachBottom 是三消 bot 的硬骨头**（本次实战 L10/15 在此卡住）：原料沿格子的 `sequence`（orderInSequence 0=底部出口）下落，**不是直线列**。bot 要推进它，必须奖励"清除该原料下落序列上、更靠近出口的格子"，而非"清同列下方"。务必把**下落序列的数据结构和方向**摸清。

### C.3 目标推进路径矩阵（评分函数的核心输入）

为 Module A 的每个 `goal_NNN`，明确"一次什么样的交换能推进它一步"。这是 Module C 最重要的产出——直接对应步骤3评分规则。

| 目标 ID | 目标类型 | 载体 | 推进一步的交换特征 | 对应评分规则 |
|--------|---------|------|---------------------|-------------|
| goal_xxx | Destroy(某色) | 糖果颜色 | 匹配线包含该色棋子 | 该色命中数 × 权重 |
| goal_xxx | Destroy/Clear(块) | 棋盘块(如 sugar) | 匹配线经过 / 相邻该块格 | 块命中数 × 权重 |
| goal_xxx | Spread | 扩散块 | 匹配相邻扩散块；或特殊糖整行/列扫 | 相邻扩散数 × 高权重 + 特殊糖激活 |
| goal_xxx | ReachBottom | 原料棋子 | 清除原料下落序列上靠近出口的格 | 序列下游格加成（近出口更高） |

> 关键设计原则：**每个目标必须能映射到"网格上某些 cell 的加分"**。bot 评分时枚举所有交换，对每个交换模拟匹配线，累加被命中 cell 的目标加分 → 选总分最高的交换。

### C.4 多目标聚焦规则

多数关卡有 2-3 个目标。精读后明确：

| 字段 | 说明 |
|------|------|
| 目标并列关系 | 是否所有目标都达成才算赢（通常是） |
| 难度不均 | 哪类目标天然更难 / 量更大（如棋盘块目标常需清几十上百个） |
| 聚焦策略 | bot 应优先推进"剩余量最大 / 最难"的瓶颈目标，而非平均用力 |

> **本次实战教训**：多目标平均用力会导致"完成简单目标、卡死难目标"的 **1/2 死局**。正确做法是按各目标**剩余量加权**，把火力集中到瓶颈目标。务必产出"如何读各目标剩余量 + 如何加权"的明确规则。

### C.5 卡死与重排规则

| 字段 | 说明 | 为什么 bot 需要知道 |
|------|------|---------|
| 死棋判定 | 棋盘何时"无可消除交换" | bot 检测到无解需主动触发重排 |
| 重排入口 | 游戏重排棋盘的方法（NoMatches 等） | 避免 bot 在死棋盘上空耗到超时 |
| 限制不减=卡死 | 步数 / 时间停止变化是卡死信号 | 看门狗据此判定并重排 / 退出 |

### C.6 阻塞式 UI 与关卡流（无人值守必查）

精读关卡开始 / 结束 / 教程 / 弹窗代码：

| 字段 | 说明 |
|------|------|
| 关卡进入 | 如何程序化进入指定关卡（跳过地图 / 关卡选择） |
| 教程拦截 | 首关 / 特定关是否有教程拦截输入，如何跳过 |
| 子关卡切换 | 多子关卡（sublevel）结构如何切换，bot 驱动循环要覆盖全部 |
| 终局弹窗 | 通关 / 失败结算屏，如何检测与关闭 |
| 体力 / 存档 | 是否消耗体力（耗尽无法开局）、存档如何重置为 fresh run |

> 三消常有"教程拦截"和"多子关卡"两个无人值守坑：教程会吃掉输入，bot 须主动清除；驱动循环须用 `while(inLevel)` 覆盖所有子关卡，否则跑完第一个子关就停。

## 评估重点

本模块的评估重点：**逻辑一致性**。

- **（必查）C.1 "非法交换是否回退"的结论是否正确？** —— 这决定 bot 是贪心单步还是多步搜索架构，判断错则架构选型与整轮迭代作废。
- **（必查）C.2 "下落是否沿垂直列"是否正确？碎片棋盘的下落序列数据结构是否摸清？** —— ReachBottom 类目标在此卡死。
- C.3 目标推进路径矩阵是否覆盖 Module A 所有目标？每个目标是否都映射到了"网格 cell 加分"规则？
- C.3/C.4 目标载体（颜色 vs 棋盘块）是否与 Module B 一致？`color=-1` 目标是否按棋盘块处理？
- C.4 多目标聚焦的"剩余量读取 + 加权"规则是否明确可编码？
- C.5 死棋判定与重排入口是否与代码一致？
- C.6 关卡进入 / 教程跳过 / 子关卡循环 / 终局检测是否都覆盖？
