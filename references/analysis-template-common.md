# 分析报告模板 — 通用基础层

> 所有游戏类型的分析报告都必须包含以下基础层。本层只定义报告的顶层结构骨架，不预设任何游戏概念。具体记录什么内容、什么字段，全部由类型深度层定义。
>
> 为什么不预设概念：不同游戏的核心逻辑完全不同。割草游戏的关键是"敌人威胁分级"，三消游戏的关键是"棋盘状态和连锁机制"，塔防游戏的关键是"塔配置和路径覆盖"。如果把"敌人分析"放在通用层，三消游戏的报告就会出现一个永远为空的章节。

---

## 通用基础层结构

所有游戏的分析报告必须包含以下章节：

```markdown
# [游戏名称] 游戏分析报告

## 游戏类型与核心玩法
（一句话概括游戏类型，如：横版动作RPG、塔防策略、卡牌养成、三消休闲等。这个字段决定了后续加载哪个类型深度层模板）

## 关卡与胜利条件
- 关卡结构：（有多少关卡/局，是否有章节划分）
- 胜利条件：（每个关卡/局的通关条件是什么）
- 目标达成方法：（达到胜利条件的主要路径）

## 核心机制
（该游戏的核心玩法机制是什么——这是通用层唯一不预设内容的章节，具体内容由类型深度层填充。例如：割草类会在这里分析敌人威胁体系和闪避机制，三消类会分析棋盘规则和连锁机制，塔防类会分析塔属性和路径机制）

## 辅助系统
（不属于核心玩法但影响bot决策的系统，如道具系统、升级系统、物理系统等。具体内容由类型深度层定义，不是所有游戏都有这些系统）

## 物理系统
- 使用的物理特性：（碰撞检测、重力、射线等，如果游戏不使用物理系统则标注"无"）
- 物理对玩法的影响：（哪些核心机制依赖物理系统，如果没有则标注"无影响"）
```

### 字段说明

| 章节 | 说明 |
|------|------|
| 游戏类型与核心玩法 | 必须填写。这个字段是类型深度层的触发器——识别出游戏类型后，加载对应的深度层模板追加分析 |
| 关卡与胜利条件 | 必须填写。所有游戏都有关卡/局和胜负判定 |
| 核心机制 | 必须填写但内容由类型深度层定义。通用层只占位，不预设"敌人"、"棋盘"等具体概念 |
| 辅助系统 | 按需填写。不是所有游戏都有道具/升级等辅助系统 |
| 物理系统 | 按需填写。不使用物理的游戏标注"无" |

---

## 类型深度层

通用基础层定义了骨架（章节结构）。类型深度层填充核心机制和辅助系统的具体内容，并追加该类型特有的章节：

- **动作/割草类** → 按顺序读取 3 个模块模板：
  - `references/analysis-template-action-A-scan.md`（实体扫描）→ 产出扫描清单，评估完整性
  - `references/analysis-template-action-B-deepdive.md`（实体深挖）→ 产出属性文档，评估准确性
  - `references/analysis-template-action-C-interaction.md`（交互与系统）→ 产出交互文档，评估逻辑一致性
  - 每个模块评估通过后才进入下一个，发现关键问题回到当前模块修正
  - 注意：策略设计不在本步骤中进行，步骤2会基于 A/B/C 的分析结果进行头脑风暴来设计 bot 策略
- 其他类型的深度层模板后续按需新增，每个类型的模板放在 `references/analysis-template-<type>-A/B/C-*.md` 中，按相同模块模式组织（不包含策略设计模块）
