# 无 VLM 的纯 Log 诊断法

> 步骤6迭代循环中，当 VLM 视频分析不可用时（缺 `DASHSCOPE_API_KEY`、无网络、用户主动暂缓），用本方法作为 VLM 的**一等替代**，而不是临时凑合。核心思想：**视频靠"看"，纯 log 靠"插桩 + 周期快照 + 规则诊断"**——用密集的内部状态记录补偿看不到画面的信息缺失。

## 与 VLM 的分工对照

| 维度 | VLM 视频 | 纯 log（本方法） |
|------|---------|-----------------|
| "bot 在做什么" | 直接看画面 | 靠周期状态快照重建（位置/状态/朝向/目标） |
| "为什么走到这个结局" | 看完整叙事 | 靠 decision_trace + critical_turns + 进度曲线还原 |
| "画面外/数值" | 推断 | 直接读字段（最强项，比 VLM 准） |
| 弱项 | 看不到精确数值 | 看不到"地面预警标记/视觉拥挤"等纯视觉信号 |

→ 纯 log 在**数值与决策推理**上甚至比 VLM 强；它的盲区是纯视觉信号，需用更密的插桩（如"附近敌人数""到最近威胁距离""是否在预警区内"）显式记录来弥补。

## 必备插桩（开始迭代前先验可信）

在 bot 代码里加这些记录，并**单跑一局确认数值真实**（见 SKILL.md 步骤6"先验插桩可信"），再开始调优。否则后续都是基于错误数据盲调：

1. **周期状态快照**（每 1–3s 一条，用 unscaled 时间）：
   `tick, hp%, 进度指标(已清波次/房间), 击杀数/XP等级, 附近敌人数, 到最近威胁距离, 当前bot状态(攻击/走位/撤退/闪避), 是否正在造成伤害`
2. **进度梯度指标**：`summary.progress`（见 battlelog 模板），单调朝通关方向。
3. **吞吐量**：击杀数、击杀/分钟、伤害输出总量（确认 bot 真的在输出，而非空走位）。
4. **伤害来源/承受**：`damage_taken.by_source`、`damage_dealt.by_target_type`。
5. **关键事件**：升级选择、首次遇到新敌人、HP 暴跌、终局原因。

> 关键陷阱：很多"策略问题"其实是**插桩或感知问题**。例如"每局升级数恒为1" → 先怀疑攻击根本没触发或XP没采集（查吞吐/控制耦合），**不要去调走位**。

## 症状 → 根因层 → 验证手段对照表

调优前先用此表把问题归到正确的"层"，避免在错误的层反复盲调（最常见的浪费）：

| 症状 | 最可能的根因层 | 先验证什么（而不是先调走位） |
|------|--------------|------------------------------|
| 吞吐≈0 / 升级数恒为初始值 / 伤害输出为0 | **控制或感知层**（不是策略） | 攻击是否真触发？是否因"移动禁攻击"而从没开火（见 Module C 控制耦合）？目标是否进入攻击范围？观察器是否真读到敌人？ |
| 进度指标长期不涨但能久活 | **目标函数错位** | bot 是否把"存活"当目标在原地苟活？检查是否朝击杀/推进优化，而非躲避优先 |
| 数值明显失真（HP恒满却死、伤害恒0） | **插桩不可信** | 先修插桩，停止一切策略调优 |
| 同一改动每局结果方差极大 | **环境/时序** | 游戏速度过高致反应不及？存档未清致续玩？并发存档串扰？ |
| 稳定在某波/某房间死亡 | **该波次的策略/build 不足** | 看 critical_turns + damage_taken.by_source 定位是哪类敌人，再针对性调 |
| bot 卡住不动 / 一直循环同一动作 | **决策死锁/局部极小值/阻塞UI未处理** | 查是否阻塞UI未关、合力为零无逃逸、状态机来回切换 |

## 联合诊断（替代 VLM+log 合并）

VLM 不可用时，用 **数值快照序列 + 决策追踪** 还原叙事：

1. 画出进度/HP/附近敌人数随时间的曲线（从周期快照），找"拐点"——HP 暴跌前 bot 在做什么、附近威胁是什么。
2. 在拐点对齐 decision_trace：bot 当时选了什么、理由（效用评分）是什么。
3. 得出可执行结论，例：
   - 快照："t=30s 附近敌人数从2跳到6，hp 90→20，bot状态=攻击(holding)"
   - decision_trace："t=29s 选择继续holding输出，未撤退"
   - 诊断："holding 时长过长 + 无'附近敌人数突增即撤离'规则 → 被成群近战瞬间集火。建议：附近敌人数>阈值时立即转 reposition。"

## 每轮报告（无 VLM 版）

沿用 SKILL.md 的每轮报告结构，但把"VLM 视频分析洞察"替换为：

- **进度曲线分析**：本轮进度指标 vs 上轮（涨了/平了/退了）+ 吞吐变化
- **拐点诊断**：从快照序列定位的关键转折 + 对齐的决策推理
- **数值证据**：伤害来源分布、卡死波次、终局原因

> 一旦条件允许（拿到 API key），切回 VLM + log 联合分析——视觉信号（地面预警、视觉拥挤、走位轨迹美感）仍是纯 log 难以替代的。本方法是高质量的过渡，不是永久替代。
