# 三消/方块消除类分析模板 — Module A: 实体扫描

> 适用于：Candy Crush / Sweet Sugar 类、宝石迷阵类、任何"交换相邻棋子凑成 3+ 连消除、按目标完成关卡"的网格消除游戏

## 使用说明

本模板是三消类分析的第 1 个模块（共 3 个）。执行顺序：A → B → C。

**认知任务类型**：广度优先搜索。遍历代码找所有"棋子 / 特殊糖 / 棋盘块 / 目标类型 / 限制类型"，不做属性分析。

**产出**：扫描清单文档——只记录"什么东西存在、在哪里、对应代码枚举/类"，不做行为分析。后续模块通过本清单分配的实体 ID 引用。

**评估重点**：完整性——是否遗漏了任何棋子类型、特殊糖、棋盘块、目标动作、限制类型？

> **三消与动作类的关键差异**：三消没有"敌人 / 弹幕 / 走位"。它的"实体"是**棋子颜色、特殊糖、棋盘块（jelly/sugar/spread/ingredient/bomb）、目标类型（Destroy/Clear/ReachBottom/Spread）、限制类型（步数/时间）**。决策不是"躲避"，而是"枚举所有交换 → 选最推进目标的那个"。务必按三消的本体来扫描，不要硬套动作类字段。

## Module A: 实体扫描

### A.1 普通棋子（颜色）清单

扫描代码中所有 Item / Candy / Gem / ItemsTypes 相关的枚举、类、配置：

| 字段 | 说明 |
|------|------|
| ID | 唯一标识，格式 `item_NNN`（如 item_001） |
| 名称 | 棋子类型名（枚举值 / 类名） |
| 颜色 id | 代码中标识颜色的整数 / 枚举（bot 用它判断"同色可消"） |
| 代码位置 | 定义该棋子的枚举 / 类 + 文件路径 |
| 一句话描述 | 如"红色普通糖果"、"可参与匹配的标准棋子" |

> 关键：找到 **"普通可交换可匹配棋子"的判定字段**（如 `currentType==NONE && Combinable`）。bot 只对这类棋子枚举交换——这是求解器网格构建的基础。

### A.2 特殊糖 / 特殊棋子清单

扫描代码中所有由 4+ 连 / L/T 形 / 5 连生成的特殊棋子（striped / wrapped / package / color bomb 等）：

| 字段 | 说明 |
|------|------|
| ID | 唯一标识，格式 `special_NNN` |
| 名称 | 特殊糖类型名 |
| 生成条件 | 由什么形状匹配生成（4 连横 / 4 连竖 / L/T / 5 连） |
| 爆炸范围 | 激活后清除什么（整行 / 整列 / 3×3 / 同色全清） |
| 激活方式 | 如何引爆（与相邻棋子交换 / 被连锁触发） |
| 代码位置 | 类名 + 文件路径 |

> 关键：记录**每种特殊糖的"爆炸方向 / 范围"和"激活入口方法"**。这是 bot 用特殊糖破"吞吐量瓶颈"关卡（高密度棋盘块）的核心武器。

### A.3 棋盘块 / 障碍 / 目标方块清单（最易漏，最关键）

扫描代码中所有 SquareTypes / Block / 覆盖在格子上的目标方块（jelly、sugar、chocolate/spread、cage、wire、ingredient 入口等）：

| 字段 | 说明 |
|------|------|
| ID | 唯一标识，格式 `block_NNN` |
| 名称 | 方块类型名（枚举值，如 SugarSquare / JellyBlock / ThrivingBlock） |
| 载体 | 是"格子属性"还是"独立棋子"？（sugar/jelly 在格子上；ingredient 是棋子） |
| 清除方式 | 如何消除一层（相邻匹配 / 其上棋子被消 / 落到底部出口 / 特殊糖波及） |
| 是否扩散 | 是否每回合自我增殖（chocolate/spread 类） |
| 代码位置 | 枚举 + 处理类 + 文件路径 |
| 一句话描述 | 如"糖霜覆盖格子，消除其上糖果即清一层" |

> **这是三消 bot 最大的盲区**（本次实战中 SugarSquare 卡死 L45/50/55 多轮）。很多"目标"不是糖果颜色，而是**覆盖在格子上的块**——bot 若按"匹配颜色"去推进，会完全看不到它（focusCells=0）。务必把每种块的**"载体（格子属性 vs 棋子）"和"清除一层的确切触发条件"**扫清楚。

### A.4 目标类型（胜利条件）清单

扫描代码中目标 / 收集动作枚举（CollectingTypes 等）和各目标的实现类：

| 字段 | 说明 |
|------|------|
| ID | 唯一标识，格式 `goal_NNN` |
| 动作类型 | Destroy / Clear / ReachBottom / Spread / CollectItems 等枚举值 |
| 目标对象 | 该目标针对什么（某颜色糖果 / 某块类型 / 原料 / 巧克力） |
| 完成判定 | 哪个方法判定"该目标达成"（如 `IsTotalTargetReached`） |
| 剩余量读取 | 哪个方法 / 字段读"还差多少"（如 `GetCount(game)`） |
| 代码位置 | 目标实现类 + 文件路径 |

> 关键：记录**每个目标的"剩余量读取入口"和"完成判定入口"**。bot 的评分函数靠它做**多目标聚焦**（优先推进剩余量最大的瓶颈目标，而非平均用力导致 1/2 卡死）。

### A.5 限制类型清单

扫描关卡限制（步数 / 时间）相关枚举与字段（LIMIT / limitType 等）：

| 字段 | 说明 |
|------|------|
| ID | 唯一标识，格式 `limit_NNN` |
| 类型 | MOVES（步数）/ TIME（时间） |
| 读取入口 | 哪个字段 / 方法读当前剩余步数 / 时间 |
| 代码位置 | 文件路径 |

> 关键：bot 的"超时看门狗"和"卡死检测"需要读这个值——**限制不再减少 = 棋盘卡死，需触发重排（NoMatches）**。

## 评估重点

本模块的评估重点：**完整性**。

- A.1 是否覆盖所有普通棋子颜色？是否找到"可交换可匹配"的判定字段？
- A.2 是否覆盖所有特殊糖？每种的爆炸范围与激活入口是否记录？
- **A.3 是否覆盖所有棋盘块 / 目标方块？每种块的"载体"和"清除触发条件"是否明确？**（最易漏，重点查）
- A.4 是否覆盖所有目标动作类型？每个目标的"剩余量读取"和"完成判定"入口是否找到？
- A.5 是否覆盖所有限制类型？
- 是否遗漏特殊机制（定时炸弹、笼子、果冻多层、传送带、生成器入口等）？
